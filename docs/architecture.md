# アーキテクチャ設計

音源生成の技術系譜を「生成（generation）」と「制御可能な楽器音源（controllable instrument）」の
2軸で整理し、本プロジェクトがどこに立つかを定める。

## 出所の方針（最重要）

本プロジェクトは**公開OSS・公開論文のみ**を土台とする。
`Desktop/dev/suno-ai` にある Suno のソースコード漏洩物は**解析も取り込みも一切しない**。
「Sunoが使うアーキテクチャ」として参照するのは、Suno自身が公開した OSS（Bark）と、
その土台となっている**公開研究**（下記）に限る。

## 音声生成の2系譜

### A. コーデック + 言語モデル系（生成が得意 / Suno の本流）

音声を**ニューラル音声コーデック**で離散トークン化し、その上を**自己回帰Transformer**で予測する。

```
音声 ──EnCodec/DAC──▶ 離散トークン列 ──Transformer(LM)──▶ トークン生成 ──デコーダ──▶ 音声
```

- **SoundStream** (Zeghidour 2021) / **EnCodec** (Défossez 2022) / **DAC** (Kumar 2023)
  — 音声を低ビットレートの離散トークンに圧縮する RVQ コーデック。
- **AudioLM** (Borsos 2022) — semantic token（HuBERT系）→ acoustic token の階層生成。
- **MusicLM** (2023) / **MusicGen** (Copet 2023, Meta audiocraft) — テキスト条件の音楽生成。
- **Bark**（github.com/suno-ai/bark, Suno公開, MIT）— text → semantic → coarse acoustic → fine acoustic
  の3段Transformer。EnCodec（8コードブック×1024, 75Hz）トークンを生成する。
  **Sunoが公開しているアーキテクチャの実体**。
- **Suno本体（Chirp/v3-v5）は非公開**。ただしCEO Mikey Shulman は公開インタビューで
  「拡散でなく自己回帰Transformerを選好」「secret sauce は音声の適切なトークン化」
  「次のトークンの確率分布を予測」と明言しており、本体もこの A 系譜にある可能性が高い
  （レイヤー数・コーデック実装・規模は非公開のため断定不可）。

**特徴**: 任意の音・歌・楽曲を生成できる表現力。**弱点**: 出力はトークン列で、
「このノートだけピッチを変える」「弓圧をこの曲線で」といった**ノート単位の連続制御が苦手**。
本質的に「一括生成」であり、演奏楽器としての細かな操作性は設計思想の外。

### B. 微分可能DSP / 物理モデル系（制御が得意 / 本プロジェクトの主軸）

合成器そのものを**微分可能**に作り、ニューラルネットには「波形」ではなく
**合成パラメータ（f0・倍音分布・雑音・物理係数）**を予測させる。

```
音声 ──分析──▶ [f0, loudness] ──小型NN──▶ 合成パラメータ ──微分可能シンセ──▶ 音声
                                    ▲ multi-scale STFT loss で逆伝播
```

- **DDSP** (Engel 2020) — harmonic+noise を微分可能実装。少量データで音色を学習。
- **微分可能モーダル/導波管** (Diaz 2023, Zheleznov 2025 等) — 物理パラメータを勾配で逆推定。

**特徴**: f0/loudness を入力に与えれば**任意ピッチ・強弱で演奏可能**＝MIDI/MPE 直結。
軽量で実時間推論可。**弱点**: 任意の音の"生成"はできない（楽器音色の再現に特化）。

## 本プロジェクトの立ち位置

目標は「MIDIで弾ける物理モデル音源」。よって主軸は **B**。
ただし A の資産を**特徴抽出・データ整備**に活用する:

| 段 | 使う技術 | 役割 |
|---|---|---|
| データ整備 | **Demucs** | ミックス→楽器ステム分離（学習ターゲット抽出） |
| 特徴抽出 | CREPE / 自己相関, （将来）EnCodec埋め込み | f0・ラウドネス・音色特徴 |
| 音色学習 | **DDSP**（本リポで学習完走） | f0/loudnessから楽器音色を制御可能に再構成 |
| 物理精緻化 | モーダル/導波管 逆推定 | 打楽器・撥弦の物理パラメータ抽出 |
| 演奏制御 | MIDI 2.0 / MPE | ノート単位の連続表現 |
| 製品化 | JUCE (VST3/CLAP) | プラグイン化 |

## RTX4090（24GB）での現実的な学習範囲

| 対象 | 可否 | 備考 |
|---|---|---|
| 小型DDSP（本リポ, 0.7M params） | ◎ | 数分で収束。単一楽器の音色学習 |
| EnCodec/DAC のファインチューニング | ○ | 事前学習済みを微調整する範囲なら可 |
| MusicGen small のファインチューニング | △ | 可能だが要工夫（メモリ/時間） |
| コーデック+LM をフルスクラッチ学習 | × | 大規模データ・多GPU前提で非現実的 |

結論: **フルスクラッチの生成モデル（Suno本流A）を作るのは非現実的**。
現実的かつ目標に直結するのは **B（DDSP＋物理モデル）を自前で学習し、
A の公開資産（Demucs, コーデック埋め込み）を前処理に使う**構成。
